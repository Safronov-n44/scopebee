Properties6

gameObject

public GameObject gameObject

The object this component is attached to. Losing the owner is what makes a component dead: on destruction the field is nulled while the memory of the component itself stays valid, so a reference held in someone else’s field reads null instead of dangling.

Example 
if (other.gameObject.CompareTag("Player"))
{
    Destroy(gameObject);
}

transform

public Transform transform { get; }

The owner’s Transform. On a destroyed component it returns null rather than dereferencing a dead owner.

enabled

public bool enabled { get; set; }

Whether the engine ticks this component. Writing it dispatches OnEnable or OnDisable, marks the UI layout dirty and calls OnEnabledChanged before either hook, so a component can release what it holds in the right order.

Note. The gate applies to every component, not only to scripts: a disabled AudioSource, Collider2D or ScrollRect stops ticking the same way. Setting the same value twice does nothing.

Example 
// OnDisable fires here, inside the assignment.
GetComponent<SpriteRenderer>().enabled = false;

tag

public String tag { get; set; }

The owner’s tag. Reading it hands back the object’s own string; assigning copies into it. To compare, use CompareTag — it does not allocate.

destroyed

public bool destroyed

Set the moment Destroy is called, long before the component is actually removed. A marked component stops being ticked in that same frame, but stays attached to its object until the end of it.

SupportsEnabled

public virtual bool SupportsEnabled { get; }

Whether this component has anything to switch off. The inspector draws the checkbox in the component header by this flag: Transform, RectTransform and Grid have no logic to run, and a checkbox that does nothing is worse than no checkbox.

TryGetComponent<T>

public Result<T> TryGetComponent<T>() where T : class

The same search in the Beef-canonical form: a Result instead of a null. The constraint is class rather than Component, so an interface implemented by a component works too.

Returns

Result<T>Ok with the component, or Err when the object has none.

Example 
if (TryGetComponent<Animator>() case .Ok(let animator))
{
    animator.Play("Idle");
}

Instantiate

public static GameObject Instantiate(GameObject original)

public static GameObject Instantiate(GameObject original, Vector3 position, Quaternion rotation)

public static GameObject Instantiate(GameObject original, Vector3 position, Quaternion rotation, Transform parent)

public static GameObject Instantiate(GameObject original, Transform parent)

public static T Instantiate<T>(T original) where T : Component

public static T Instantiate<T>(T original, Vector3 position, Quaternion rotation) where T : Component

public static T Instantiate<T>(T original, Vector3 position, Quaternion rotation, Transform parent) where T : Component

public static T Instantiate<T>(T original, Transform parent) where T : Component

Clones an object with its whole hierarchy and puts the clone into the active scene, or under the parent you name. The generic forms take and return a component type: a prefab field is often typed by the script on it, and the clone’s own instance of that script is what you want back.

Parameters

originalGameObjectThe object to clone. A null returns null and logs an error. positionVector3Local position of the clone. rotationQuaternionLocal rotation of the clone. parentTransformParent for the clone. Without one the clone becomes a root object of the active scene.

Returns

GameObjectthe clone — or, in the generic forms, T on the clone.

Note. The transform is set before the clone’s Awake and OnEnable run, and OnPlayStart follows across the whole hierarchy. That order is the reason a cloned Rigidbody2D creates its physics body where the instance is, not where the prefab was.

Example 
private void Shoot()
{
    let bullet = Instantiate(_bulletPrefab, transform.position, .identity);
    bullet.GetComponent<Rigidbody2D>().velocity = .(0, 12);
}

Destroy

public static void Destroy(GameObject obj)

public static void Destroy(GameObject obj, float delay)

public static void Destroy(Component comp)

public static void Destroy(Component comp, float delay)

Schedules destruction. Nothing is removed on the spot: the target is marked, stops being ticked immediately, and is taken out at the end of the frame, after LateUpdate, when the traversal stack is unwound and the physics step is done.

Parameters

delayfloatSeconds to wait before removal. Zero means the end of this frame.

Note. The queue belongs to the scene that owns the target, not to the active one — a DontDestroyOnLoad object is destroyed by its own scene.

Example 
// The explosion cleans itself up two seconds later.
Destroy(gameObject, 2f);

DontDestroyOnLoad

public static void DontDestroyOnLoad(GameObject target)

public static void DontDestroyOnLoad(Component target)

Moves the object into the persistent scene, which survives a scene change and ticks alongside the active one. The Component form moves the owner, for converted code that passes this.

Note. The move itself is deferred to the end of the frame: it mutates the scene’s root list, and it is called from inside Awake, Start or Update, with that list being walked.

IsDestroyedReference

public static bool IsDestroyedReference(Object obj)

One check of “this reference points at a destroyed participant of the scene” for code that holds a field as Object and does not know its type — the serialiser and the automatic inspector. A GameObject and a component carry that mark differently, and neither caller needs to know how.

Returns

booltrue for a destroyed GameObject or component, false for anything else.

Overridable4

GetLifecycleFlags

public virtual LifecycleFlags GetLifecycleFlags()

The set of callbacks this component implements. The engine tests it before every dispatch, so a callback nobody declared is never called and costs nothing.

Note. You do not write this method. The Lifecycle attribute generates it at compile time from the list of names a component declares — the same way for engine components and for scripts.

OnValidate

public virtual void OnValidate()

Called when the inspector has written a field. The inspector writes fields directly by offset, past any property setter, so this is the only way a component learns that it was edited.

OnEnabledChanged

protected virtual void OnEnabledChanged(bool value)

A hook for the side effects of switching enabled at runtime. It runs before OnEnable or OnDisable are dispatched, which is what keeps a cancelled Invoke ahead of OnDisable and a collider’s detach ahead of its own.

OnInspectorGUI

public virtual void OnInspectorGUI()

Draws the component in the inspector. The default draws every serialised field automatically and calls OnValidate when one changes. Editor only — the method does not exist in a web build.

Operators1

operator==

public static bool operator==(Component lhs, Component rhs)

Two components are equal when they are the same reference, or when both have lost their owner. Two different dead components are not equal — List.Remove and List.Contains go through this operator, and collapsing them would take out the wrong entry.

Careful. Comparing against the null literal never reaches this operator: the compiler turns it into a pointer check, so a destroyed component still reads as alive there. What makes a stale reference safe is not the operator but the fact that the component keeps its memory until the scene unloads.
