Lifecycle

Everything the engine calls on your components, in the order it calls it.

One frame

A frame is a fixed sequence. Physics runs first and drives FixedUpdate from its own accumulator, so a fixed step can happen zero, one or several times in a frame. Then the scene is walked twice — Update over every object, then LateUpdate over every object — and only after that do the deferred queues drain.

Time.Update PhysicsManager2D.Update ──► FixedUpdate 0..n times, from the accumulator UpdateAll ──► Start (lazy) ──► Update LateUpdateAll ──► LateUpdate ProcessPendingPersist moves into the DontDestroyOnLoad scene ProcessPendingDestroy ──► OnDisable ──► OnDestroy TweenManager.Update AudioManager.Update ProcessPendingLoad a scene change requested during the frame

Note. The DontDestroyOnLoad scene ticks alongside the active one, phase by phase.

How the scene is walked

Inside a scene the order is: an object’s own components in the order they were added, then its children, depth first.

The enabled gate applies to every component, not only to scripts.

Coming into the scene

  • OnInit — runs the moment the component is attached.
  • Awake — is where a component finds what it needs on its own object.
  • OnEnable — runs when the component becomes enabled.
  • Start — is lazy.
  • OnPlayStart — creates the runtime resources that only exist while the game is playing.

Guaranteed. Awake is dispatched exactly once per component, and OnDisable only ever reaches a component that received OnEnable.

Leaving it

Destroy does not delete anything on the spot.

On removal the component gets OnDisable and then OnDestroy, and only then loses its owner.

Careful. Because destruction is deferred, an object destroyed early in a frame is still attached for the rest of it.

Every callback

  • Update — once per frame, for every enabled component.
  • FixedUpdate — from the physics accumulator.
  • LateUpdate — after every object has had its Update.
  • OnBecameVisible, OnBecameInvisible — when the game camera starts or stops seeing the object.
  • OnCollisionEnter2D, OnCollisionExit2D, OnTriggerEnter2D, OnTriggerExit2D — from the contact events of the physics world.
  • OnDrawGizmos, OnDrawGizmosSelected — draw into the scene view of the editor.

Declaring them

A script lists the callbacks it implements in the Lifecycle attribute.

[Lifecycle("OnEnable", "FixedUpdate", "OnCollisionEnter2D")]
public class Bird : CoBehaviour
{
    private bool _alive;

    private void OnEnable()
    {
        _alive = true;
    }

    private void FixedUpdate()
    {
        // Runs on the physics clock, not the frame clock.
    }

    private void OnCollisionEnter2D(Collision2D collision)
    {
        _alive = false;
    }
}
